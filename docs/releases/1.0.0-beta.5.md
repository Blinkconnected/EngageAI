# Release Report — v1.0.0-beta.5

**Date**: 2026-07-28
**Channel**: beta
**Scope**: AI Autopilot activation modes and usage reporting; the
five-column conversation workspace; agent-deletion and layout fixes.

---

## Summary

Two headline pieces of work.

**AI Autopilot** gained two new ways to engage, alongside the one it
already had. Its reply-or-hand-off decision moved out of the
message-driven consumer into a shared `AutopilotService`, because the two
new triggers do not have a message to react to — an SLA breach fires
precisely *because* nobody replied. Usage is now tracked per agent, with
the trigger recorded, so supervisors can separate AI an agent asked for
from AI that stepped in on its own.

**The conversation workspace** became the specified five columns, with
each column owning its own scroll region and the page itself never
scrolling. This was verified in a real browser rather than by reasoning
about CSS — which mattered: the "page never scrolls" rule had been
declared fixed twice while still being broken in practice.

---

## UX changes

- **Five-column workspace**: `Sidebar | Filters & Queues | Conversation
  List | Conversation | Customer Details`. Filters & Queues is a
  dedicated column, not tabs stacked above the list; filter state lives
  in the URL so it survives opening a conversation and returning.
- **Independent scrolling per column**, with the page itself never
  scrolling vertically. Verified at 1680 / 1500 / 1280 / 820px.
- **Sticky composer**: the reply box keeps its full height and position
  while the message history scrolls beneath it.
- **Opening a conversation lands on its newest message**, including when
  switching conversations after having scrolled up in a previous one.
- **"Ask AI to reply"** in the conversation's details column — the agent
  request activation mode. Hidden once Autopilot owns the conversation.
- **Autopilot activation modes** in Settings → AI, with a warning when
  Autopilot is enabled but no mode can start it.
- **AI usage reporting**: a per-agent breakdown and a usage trend with a
  daily/weekly/monthly toggle on the Reports → AI Usage tab.
- Two spacing defects fixed that screenshots exposed: the details
  column's actions overlapped at 280px, and the AI Summary label ran into
  its button.

## Technical changes

- **`AutopilotService`** (`application/services/autopilot_service.py`)
  owns the reply-or-hand-off decision for all three triggers
  (`new_message`, `sla`, `agent_request`). Per-mode gating lives here,
  not in each caller, so the triggers cannot drift on what "enabled"
  means. `new_message` is exempt from its own mode check — a conversation
  Autopilot already owns must keep being answered even if an admin later
  disables that activation mode, rather than being stranded mid-thread.
- **`autopilot_sla_consumer`** binds `conversation.sla_warning` and
  `conversation.sla_breached`. Registered in both compose files.
- **Idempotency**: the SLA trigger only acts when the newest message is
  *inbound*. This is a direction check, not an id comparison — replying
  adds a message, so after the first run the newest id is Autopilot's own
  reply. Without this a warning and its follow-up breach replied twice.
- **The AI provider is built lazily**, only after a run clears every
  cheap eligibility gate; the common case is a conversation Autopilot
  does not own, and that must stay free.
- **`AppLayout` root is `height: 100dvh; overflow: hidden`.** With only
  `minHeight: '100%'` the shell had no definite height to distribute, so
  `main` could not size against anything and the document scrolled —
  measured at 2980px of scrollHeight in a 900px viewport with zero real
  scroll containers.
- `is_ai_assisted` / `is_ai_generated` are two distinct, non-overlapping
  provenance flags; each key is omitted when false so a manual reply
  keeps its historical empty `{}` metadata.

## Database changes

| Migration | Change |
|---|---|
| `34919b8bff0b` | Adds `agent_ai_daily_stats` — per-agent AI usage rollup, unique on `(company_id, agent_id, stat_date, operation)`, FKs to `companies`/`agents` with `ON DELETE CASCADE`, plus company/agent/company-date indexes. |

`agent_id` is NOT NULL deliberately: the upsert conflicts on the full
key, and Postgres treats NULLs as distinct in a unique constraint, so a
nullable column would insert a new row per event instead of
incrementing. Usage with nobody to attribute it to stays company-wide.

Applied and downgrade/upgrade-cycled against real PostgreSQL.

## API changes

| Endpoint | Change |
|---|---|
| `POST /conversations/{id}/autopilot` | **New.** Agent-request activation. Rides `conversations.manage`. `409` when the mode is off, `503` when no AI provider is configured. |
| `GET /reports/ai/usage` | **New.** `{by_operation, by_agent, trend, total_calls}`; `granularity=daily\|weekly\|monthly`. `reports.read`. |
| `POST /conversations/{id}/messages` | `is_ai_assisted` (optional, default false) added to the request body. |
| `PATCH /company` | `settings.ai.autopilot` gains `activate_on_new_conversation` (default **true**), `activate_on_sla`, `activate_on_agent_request` (both default false). |

New domain event `conversation.autopilot_replied` carrying `trigger`,
`confidence`, `message_id`, `assigned_agent_id` and the actor.
`ai.completed` now carries `actor_user_id`.

No permissions were added — every new surface rides an existing one.

## Known issues / limitations

- **Conversation tags** remain deferred — not part of this milestone.
- **The Inbox table page** (`/conversations`) is unchanged and still a
  paginated data grid. The five-column workspace applies to
  `/conversations/:id`; the two are complementary views, and the table
  retains triage features (queue mode, unassigned-only, Pick) the
  workspace's list column does not duplicate.
- **`GET /reports/ai/usage` has no PDF/Excel export** yet; the older
  `GET /reports/ai` retains its exports.
- **The `ai-autopilot-consumer` container had never been started** in
  this development environment before this release, so Autopilot's
  message-driven replies were not running here. It is running now, but
  any deployment created before this should confirm the service is up.
- Weekly buckets start Monday and monthly on the 1st, in UTC; there is no
  per-company week-start or timezone setting for the trend yet.
