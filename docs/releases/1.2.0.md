# Release Report — v1.2.0

**Date:** 2026-08-08
**Status:** prepared, **not tagged**. See the release gate for why.

## Summary

A hardening release. One new feature — message redaction — and the rest
is closing findings from the v1.2.0 release gate: configuration that
lied, an image set that was not reproducible, an edge nobody was
watching, and a scheduled task that had been dead for three days without
anyone noticing.

## Features implemented

**Message redaction.** Removing what a single message said while keeping
that it was said. Chosen over deletion because a message sent over
WhatsApp or email cannot be unsent: the customer keeps their copy, so
destroying ours loses our half of a record they can still produce.

Removes the body, the provider's echoed copy in metadata, attachments
from object storage, and every citation in Memory and Learning; excludes
the message from future analysis at the source query. Append-only audit
record carrying actor, timestamp, reason and ids — and never the
content. New permission `messages.redact`, Administrators and Owner
only.

See `docs/architecture/message-redaction.md`.

## Bugs fixed

- `PAYPAL_ENVIRONMENT` advertised in `.env.example` and read by nothing.
  Setting it to `live` left the platform in sandbox, healthy, taking no
  money. Removed; `PAYPAL_SANDBOX` documented as the real switch.
- `blinkengage.services.check_configuration_drift` had not run for 71
  hours against a 24-hour schedule. Root cause: the Celery worker
  process started before the code that registers the task, and Celery
  builds its registry once at import. Not a code defect — a stale
  process. Documented in the deployment guide with a verification
  command.
- 156 MB HNSW index on a zero-row table. Rebuilt to 16 kB.
- Grafana provisioning outage, self-inflicted during this release: a new
  contact point was added and the container *restarted* rather than
  recreated, so the new environment variable was never injected and
  provisioning failed the whole process. Recovered in minutes. Recorded
  because the same trap is documented in `contact-points.yml`'s own
  header and was walked into anyway.

## Breaking changes

None for API consumers.

**Operators:** a production deployment with `DEBUG=true`, default MinIO
credentials, placeholder secrets, wildcard CORS or `DATABASE_ECHO=true`
will now refuse to start. This is intended. The error lists every
problem at once.

## API changes

- `POST /conversations/{id}/messages/{message_id}/redact` — new
- `GET /message-redactions` — new
- `MessageResponse` gains `redacted_at`
- Deciding on a conversation-deletion request moved from
  `conversations.delete` to `conversations.delete_approve`

## UI changes

None in this release. The redaction endpoints are API-only; the
conversation view already renders `body: null`, and `redacted_at` is
available for the thread to mark the message.

## Known limitations

- **Redaction does not reach backups.** A set taken before the redaction
  still contains the content. Recorded in `hardening.md`; erasure
  obligations extending to backups need a documented expiry period.
- **Postgres may retain the old row version** until vacuum. Unreachable
  through SQL, not cryptographically erased.
- **The customer's own copy is untouched.** Inherent, not a defect.
- **No redaction UI.** API only in this release.
